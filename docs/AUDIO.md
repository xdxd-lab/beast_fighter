# 音訊設計與混音

Beast Brawl 的所有聲音都在執行時以 Web Audio API 合成（`js/audio/audio.js`）。不載入任何音檔，沒有下載成本，也沒有素材授權問題。

## 訊號流程

```
各聲部 ─┬─> sfxBus ──────────────┐
        └─> reverbSend → 迴旋殘響 → wet ─┤
音樂 ──────> musicBus ───────────────────┼─> master → 壓縮器 → 限幅器 → 輸出
```

- **壓縮器**（threshold −14 dB、ratio 4）：讓多個聲音疊加時聽起來是一個整體。
- **限幅器**（threshold −2 dB、ratio 20、attack 1 ms）：避免連續重擊時爆音。
- **殘響**：程式產生的 1.9 秒指數衰減脈衝響應；勝利音樂、治療、護盾等「空間感」較重的聲音送比較多。
- **聲道定位**：施放音放在出手方，命中音放在受擊方（左右約 ±0.45）。

## 小喇叭的頻段考量

筆電與手機喇叭幾乎發不出 300 Hz 以下的聲音。如果音樂的能量集中在低頻，在這些裝置上會「幾乎聽不到」。因此：

- 貝斯用鋸齒波，音域比一般貝斯高一個八度，讓泛音落在 300 Hz 以上。
- 打擊聲以 1–4 kHz 的「啪」聲與約 500 Hz 的「身體」為主，低頻正弦只作輔助。
- 響度對齊時，先做 300 Hz 高通再量 RMS，不用全頻 RMS。

## 量測結果

以下由 `python3 scripts/qa/audio_check.py` 離線渲染後量測，數值為 dBFS，使用預設音量：

| 渲染內容 | 峰值 | 全頻 RMS | RMS（>300 Hz） | 400 ms 最大值（>300 Hz） |
| --- | ---: | ---: | ---: | ---: |
| 選角 BGM（一整輪 8 小節） | −3.4 | −17.7 | −20.1 | −16.2 |
| 戰鬥 BGM（一整輪 8 小節） | −1.5 | −17.7 | −19.9 | −17.6 |
| 勝利音樂 | −0.4 | −19.6 | −19.8 | −14.4 |
| 介面音效 | −3.5 | −23.0 | −23.5 | −17.0 |
| 戰鬥音效 | 0.0 | −17.4 | −18.7 | −10.7 |
| 全部技能音效 | 0.1 | −18.7 | −19.5 | −9.6 |

- 2026-11-20 試聽回饋「音樂太小聲」後，BGM 在 300 Hz 以上的 RMS 從約 −27 dB 提高到約 −20 dB（+7 dB）；音效同步提高約 3 dB，維持在音樂之上。
- 兩首循環 BGM 在 300 Hz 以上的 RMS 相差 0.2 dB，切換畫面時不會一首大、一首小。
- 戰鬥與技能音效的短時響度比 BGM 高約 7–8 dB，在音樂中清楚可辨。
- 介面音效比戰鬥音效低約 5–6 dB，聽起來不會搶戲。
- 音樂試聽檔剛好渲染一整輪（選角約 20.9 秒、戰鬥約 13.0 秒）再加 2.5 秒殘響尾音，會在樂句結尾收住；遊戲中則無縫循環。

匯流排的微調常數是 `audio.js` 中的 `MUSIC_TRIM` 與 `SFX_TRIM`。調整後請重新執行量測腳本。

## 試聽

量測腳本會在 `.qa/audio/` 輸出 WAV 檔，可以逐一單獨試聽（macOS）：

```bash
afplay .qa/audio/music-select.wav
afplay .qa/audio/music-battle.wav
afplay .qa/audio/music-victory.wav
afplay .qa/audio/sfx-combat.wav
afplay .qa/audio/sfx-skills.wav
```

## 自動播放政策

瀏覽器規定 `AudioContext` 必須在使用者手勢中建立或恢復。遊戲在第一次 `pointerdown`、`keydown` 或 `touchend` 時解鎖音訊；在此之前要求的音樂會先記下，解鎖後才開始播放。分頁隱藏時會暫停（`suspend`），回到前景後再恢復。網址加上 `?mute=1` 會完全不建立音訊。
